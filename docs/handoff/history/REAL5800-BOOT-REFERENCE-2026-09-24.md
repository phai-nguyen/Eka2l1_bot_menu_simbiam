## No-SIM branch

The supplied real-device screenshot shows the Nokia 5800 booting without a SIM
and presenting a modal question equivalent to:

"Continue using the phone without a SIM / in offline mode?"

The shown Turkish UI has Evet (Yes) and Hayır (No).

This is product behavior to preserve as a real-device oracle even where generic
open Symbian Startup source labels the rejection path as BootIntoOnline. RM-356
product customization / downstream Starter system-state handling may turn the
no-SIM + reject combination into shutdown.

## Relationship to B55-B57

B55/B56/B57 reach a stable blank white Startup surface.

B57 proves that this white surface is guest-generated by Startup.exe itself:

- full-screen BLIT
- full-screen white CLEAR_RECT
- full-screen white CLEAR

Therefore the current NATIVEBOOT2 output has reached a visually legitimate
intermediate stage of real Nokia boot.

However it is not yet a completed phase. On the real device, white progresses
to one or more of:

- no-SIM/offline query (when applicable)
- NOKIA/hands welcome animation
- first-boot date/time queries
- Idle/home screen

A blank white surface that remains indefinitely is therefore a state-machine
stall, not the expected final rendering.

## Relevant Startup source state machine

Official Startup source identifies:

KPSUidStartupApp = 0x100058F4
KPSStartupAppState = 1

States:

1 = EStartupAppStateWait
2 = EStartupAppStateStartAnimations
3 = EStartupAppStateFinished

Startup enters a waiting phase and the welcome animation only begins after the
startup synchronization path allows progression.

Generic source sequence includes:

WaitingCriticalBlock
 -> OfflineModeQuery
 -> WaitingShowStartupAnimation
 -> ShowingWelcomeAnimation
 -> ShowingOperatorAnimation / FirstBootAndRTCCheck
 -> StartupOK

The supplied real-device behavior is authoritative for RM-356 where product
customization differs from the generic open-source branch.

## Immediate B58 interpretation

B58 should determine whether 0x100058F4:1 is:

- set to Wait=1;
- later advanced to StartAnimations=2;
- eventually set to Finished=3.

If Wait=1 occurs but StartAnimations=2 never occurs, trace the component
responsible for startup synchronization / critical block completion.

If StartAnimations=2 occurs but the display remains blank white, trace
RProperty subscription completion into StartupPubSubObserver and
WaitingStartupAnimationStartL / DoStartupShowWelcomeAnimationL.

Do not mask the stall by forcing Home or injecting a synthetic hands animation.
