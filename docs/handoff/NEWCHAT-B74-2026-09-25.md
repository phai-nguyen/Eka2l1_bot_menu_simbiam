## Proven current blocker

Telephone UID3 0x100058B3 reaches native Startup and then shows:

Phone start-up failed. Contact the retailer.

B73 proved:
- phoneui.r01 exists and parses correctly;
- Telephone performs valid FileServer Entry/Open/Size/Seek/Read/Close on it;
- actual requested resource ID at CONE14 is 0x1099B02D;
- matching RM-356 SYM.RPKG maps that ID to:
  Z:\resource\apps\callhandlingui.r01
  resource index 0x2D / 45;
- callhandlingui.r01 and localized callhandlingui.r96 both exist;
- no callhandlingui.r01 open/registration occurs before the panic.

Nokia PhoneUI source shows CPhoneResourceResolverBase::BaseConstructL()
intends to register:
1. phoneui.rsc
2. callhandlingui.rsc
3. phoneuitouch.rsc

CONE source shows resource lookup panics when no registered resource file owns
the requested ID.

Therefore the first proven blocker is:
callhandlingui resource exists on Z but is not registered before PhoneUIUtils
requests 0x1099B02D.

## B74 purpose

B74 is diagnostic-only. It captures saved Telephone guest context around
PhoneUI resource registration to prove the exact caller/control-flow boundary
after phoneui.r01 and before missing callhandlingui registration.

Markers:
- [NBOOT2][PHONEUI_RES_CALLER]
- [NBOOT2][PHONEUI_RES_FRAME]
- [NBOOT2][PHONEUI_RES_ID]
- [NBOOT2][PHONEUI_RES_CONTEXT_DONE]

It tags addresses inside the exact RM-356 PhoneUIUtils.dll and cone.dll runtime
ranges and scans a bounded 96-word guest stack.

Do not register callhandlingui in B74 itself.

Do not force ESimUsable.
